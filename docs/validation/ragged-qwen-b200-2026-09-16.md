# Ragged Qwen3-MoE B200 validation — 2026-09-16

Issue: [#29](https://github.com/HectorHHZ/Less-is-MoE/issues/29).
Implementation: [PR #30](https://github.com/HectorHHZ/Less-is-MoE/pull/30).
Machine-readable evidence: [JSON report](ragged-qwen-b200-2026-09-16.json).

## Outcome

Both IntDim-L and IntDim-G complete calibration-based selection, physical
compaction, config/weight export, exact HF weight reload and custom vLLM GPU
generation. Validation includes the **entire pretrained
Qwen/Qwen3-Coder-30B-A3B-Instruct checkpoint**, in addition to a tiny random
Qwen3-MoE fixture. No layers or experts were removed to make the pretrained
model fit; only the selected intermediate neurons were compacted.

| Case | Layers / experts per layer / hidden size | Original → compact parameters | Retained widths | vLLM result |
| --- | --- | --- | --- | --- |
| Random fixture, L | 2 / 4 / 128 | 952,192 → 558,976 | 8–232, 8 distinct | Both prompts: 4/4 tokens match stock zero-mask |
| Random fixture, G | 2 / 4 / 128 | 952,192 → 558,976 | 2–239, 8 distinct | Both prompts: 4/4 tokens match stock zero-mask |
| Full pretrained, L | 48 / 128 / 2048 | 30,532,122,624 → 16,036,608,000 | 0–768, 451 distinct | Code prompt: 16/16 match; second prompt: first 15/16 match |
| Full pretrained, G | 48 / 128 / 2048 | 30,532,122,624 → 16,036,608,000 | 0–768, 413 distinct | Both prompts: 16/16 tokens match stock zero-mask |

The target drop ratio is 50% of routed expert intermediate neurons. Embeddings,
attention, routers and other parameters remain, so total parameter reduction
is less than 50%. Zero-width experts preserve their original router positions.

## Environment and settings

- One NVIDIA B200 (host GPU 5), CUDA compute capability 10.0.
- Unified base image ID:
  `sha256:959d2ed008772283e20a0d7302eb9663be56c1dea51122e2451ce3ff1f1d3cb1`.
  PR project code was mounted and installed editable with `--no-deps`;
  third-party dependencies were unchanged.
- Python 3.12.14; PyTorch 2.13.0+cu130; Transformers 5.17.0;
  vLLM 0.29.0; CUDA 13.0 runtime, image toolkit 13.0.3.
- GPU model execution only; BF16. FP32 expert diagnostics also execute on GPU.
- vLLM: TP=1, eager, Triton attention, context 256, at most two sequences,
  greedy generation (`temperature=0`), `ignore_eos=True`, seed 7.
  The baseline uses stock Triton MoE; compact checkpoints use the new ragged
  Triton backend. Four generated tokens per tiny prompt; 16 per full prompt.
- Full model calibration: the four committed texts in
  `docker/ragged_qwen_smoke.py`, token lengths **21, 19, 23, 19**. Scores were
  computed once on the complete model and reused for L/G. This is a smoke
  calibration of 82 tokens, not a quality-evaluation protocol.
- Two held-out prompts: a Fibonacci code completion and a short explanatory
  request. Outputs in the JSON are model-generated test data, not verified
  answers.

## Correctness evidence and limits

- **15 GPU tests passed**, including actual CLI L/G export/reload, mismatched
  widths, unaligned widths, zero-width experts, all-zero expert layers,
  invalid plans and invalid metadata.
- All HF compact checkpoint tensors reload **bitwise exactly**. Reloaded HF
  logits also match the corresponding in-memory compact model exactly.
- Tiny BF16 zero-mask and compact HF logits have maximum absolute error **0**
  on the held-out prompts.
- Full-model FP32 checks sample experts 0, 64 and 127 in **every layer**,
  144 expert checks per scope, using identical GPU inputs and TF32 disabled.
  Maximum absolute errors: L **7.1526e-7**, G **5.9605e-7**. These are expert
  checks, not full-model FP32 logit comparisons.
- Full BF16 zero-mask versus compact HF logits are **not bitwise equivalent**:
  max absolute error L **0.953125**, G **1.5**. Per-prompt cosine similarities
  are L `[0.999209, 0.998241]`, G `[0.999523, 0.995558]`; reference-to-compact
  KL divergences are L `[0.007054, 0.000924]`, G `[0.005592, 0.002600]`.
  First-token argmax matches on both prompts for both scopes.
- Eight vLLM checkpoint runs succeeded: four stock zero-mask runs and four
  custom ragged runs, with two completions each. The L full-model second
  completion differs at token 16. Successful generation and small-smoke
  numerical checks do not establish full accuracy equivalence.

The first full BF16 elementwise comparison failed (`rtol=0.04`, `atol=0.25`).
The harness now separately checks FP32 expert correctness and reports BF16
distribution drift; it does not relabel the original comparison as passed.
A tiny G startup also failed when simultaneous full-model allocation disturbed
vLLM's memory profiling. The isolated retry passed; subsequent full preparation
and vLLM initialization ran serially.

No throughput/latency improvement has been measured. The backend uses compact
weights but retains a maximum-width scratch buffer and launch grid, with
unused column tiles returning early. CUDA Graph, multi-GPU, quantization and
other model families remain outside this implementation's validated scope.

## Reproduction and artifacts

See [the format and commands](../RAGGED_EXPERTS.md). Full runs use:

```bash
export VLLM_PLUGINS=less_is_moe_ragged
python -m docker.ragged_qwen_smoke prepare \
  --model /models/qwen3-coder --scope layer \
  --scores /results/full-scores.pt --output /results/full-layer
python -m docker.ragged_qwen_smoke generate \
  --output /results/full-layer --checkpoint masked --max-tokens 16 --gpu-memory-utilization 0.5
python -m docker.ragged_qwen_smoke generate \
  --output /results/full-layer --checkpoint compact --max-tokens 16 --gpu-memory-utilization 0.5
```

Repeat with scope `global` and output `full-global`. Keep preparation and
generation in separate, sequential processes. Full checkpoints and raw logs
are retained on B200 under
`/raid/x9zou/less-is-moe-ragged.Op60Um/results/`; compact checkpoints are
`full-layer/compact` and `full-global/compact`. Raw prepare memory/timing
measurements for the successful full reruns reuse cached scores and therefore
do not represent end-to-end calibration memory or throughput.
